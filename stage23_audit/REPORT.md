# t1 45°C 규칙 이후의 2↔3 오류 분석

> 이 문서는 45°C 규칙만 적용한 이전 기준의 결과다. public 0.93의 **rules3 전체를 기준으로 다시 집계한 최신 결과**는 [rules3 이후 오류 분석](/home/ubuntu/JEONGYUN/rules3_stage23/REPORT.md)에 있다. 두 기준의 오류 수와 점수를 혼용하지 않는다.

사용자 보고 최고 제출은 `submission_originalB_rule1_T1_45.csv`의 약 **0.92**다. 이번 분석은 그 규칙을 원본 B의 저장 예측에 재현한 뒤 남은 2↔3 오류만 다룬다. **Test를 읽거나 제출 CSV를 새로 만들지 않았다.** 0.92는 사용자 제공 외부 점수이고 아래 수치는 dev/validation의 내부 Macro F1이다.

## 결론

**2→3을 재현하는 보편적인 센서 임계값은 이번 분석에서 찾지 못했다. 대신 이미 3으로 판단한 뒤 다시 2로 되돌아가는 오류를 제한하는 인과적 상태 규칙이 유망하다.** 단, 모든 2↔3 오류를 제거하지 못했고 효과가 일부 실험에 집중돼 있다.

- 현재까지 최고 t1이 50°C 미만이면 3으로 올리지 않는 단방향 안전 규칙: dev 2건, validation 2건 수정, 확인된 정답 훼손 0건. 효과는 작다.
- **원본 3-seed B 앙상블이 3을 연속 10초 예측하면 그 이후 B의 2 예측만 3으로 바꾸는 규칙:** dev 32건, validation 207건 수정, 두 자료에서 기존 정답 훼손 0건. 합산 2↔3 오류 874→635건이다.
- **센서 모델로 B의 2/3 판정을 전부 대체하는 것은 추천하지 않는다.** 작은 트리와 고정 용량의 부스팅 모두 공식 validation에서 악화했다.

## 1. 오류가 단순히 경계 몇 행에만 있는 것은 아니다

45°C 규칙을 적용한 뒤:

| 실제→예측 | dev | validation |
|---|---:|---:|
| 2→3 | 150 | 64 |
| 3→2 | 271 | 389 |
| 합계 | 421 | 453 |

두 split의 합계 874건 중 실제 2→3 전환 ±60초 이내는 318건이다. 415건은 경계에서 120초보다 멀다. 즉 경계 시각을 몇 초 당기거나 미루는 것만으로 충분하지 않다.

validation의 3→2 389건 중 E16이 222건이다. dev의 3→2 271건 중 37건, validation의 389건 중 231건에서는 같은 실험에서 **이전에 이미 B가 3을 예측한 적이 있었다.** 이 부분은 '처음 3을 알아보는 문제'와 '알아본 상태를 유지하지 못하는 문제'를 구분해야 함을 보여준다.

상세: `results/error_summary.csv`, `errors23.csv`, `boundary_offsets.csv`.

## 2. 1→2의 성공이 모든 경계에 같은 형태의 규칙이 있음을 뜻하지는 않는다

97개 실험 모두의 2→3 전환을 확인했다. 해당 실험들의 라벨 경로에서 역행은 관측되지 않았다.

2→3 시점의 t1은 96개 실험에서 약 50~90°C에 퍼져 있고, 나머지 1개 실험에는 543.2°C의 급격한 값이 관측된다. 마지막 2단계 관측까지의 t1 최고값은 전체에서 88.5°C까지 올라가지만, 첫 3단계의 t1 최고값은 다른 실험에서 50.1°C부터 나타난다. 따라서 모든 실험의 경계를 정확히 재현할 단일 누적 t1 임계값의 조건인

`모든 마지막 2단계 값 < 임계값 ≤ 모든 첫 3단계 값`

을 만족시키는 수는 없다.

더 나아가 bat_class·bat_cc·soc_status·tr_method로 정확히 묶은 **18개 조건 모두** 이 t1 임계값 구간이 서로 충돌했다. 단순히 배터리 용량별 t1 임계값 하나를 정해도 모든 전환을 설명하지 못한다. 이는 다른 센서의 조합이나 기록되지 않은 기준까지 불가능하다는 증거는 아니다. 온도 값의 급변도 라벨 오류라고 단정하지 않는다.

팀원의 `find_23_events.csv`에서는 조사한 최초 가스 검출·압력 상승·온도/상승률 이벤트도 높은 전환 일치율을 보이지 않았다. **2→3의 라벨 기준이 어떤 센서인지 아직 확정되지 않았다.**

상세: `results/boundary_values.csv`, `condition_threshold_feasibility.csv`.

## 3. 임계값만 적용한 결과

새 임계값 추정은 원래 fit 62개 실험만 사용했다. dev와 validation에 동일한 fit 임계값을 적용했다. 팀원 envelope 실험과 달리 **현재 예측이 2 또는 3인 행만 수정**하고 1/4/5/6 예측은 보존했다.

| 방법 | dev 수정/훼손 | validation 수정/훼손 |
|---|---:|---:|
| t1 누적 최고값 <50이면 3→2 | 2 / 0 | 2 / 0 |
| fit 용량별 t1 상·하한 envelope | 22 / 0 | 8 / 0 |

범위 밖의 명백한 오판을 줄이는 데는 쓸 수 있으나 남은 874건을 해결할 방법은 아니다. 특히 fit의 표본 최솟값·최댓값은 물리 법칙이 아니며 새로운 실험에서도 반드시 성립한다고 보장하지 않는다.

## 4. 유망한 방법: '확인된 3단계' 상태 유지

적용 대상은 **기존 최고점 원본 B의 3-seed 확률 앙상블 + 45°C 규칙**이다.

1. 동일 실험에서 3단계 예측이 연속 10초 동안 유지되는지 확인한다. 5초 간격이면 3개 관측이 필요하다.
2. 관측 간격이 15초를 초과하면 확인 중인 연속 구간을 끊는다.
3. 확인된 이후에만 B의 2 예측을 3으로 바꾼다.
4. 1/4/5/6 예측은 보존한다. 다른 실험으로 상태를 넘기지 않는다.
5. 미래 관측, 실제 전환 시각, 실제 라벨은 입력에 사용하지 않는다.

| 지표 | 원본 B+45°C | +3 확인 10초 상태 유지 |
|---|---:|---:|
| dev 전체 Macro F1 | 0.787871 | 0.792072 |
| dev 3→2 오류 | 271 | 239 |
| dev 2→3 오류 | 150 | 150 |
| validation 전체 Macro F1 | 0.712880 | 0.733250 |
| validation 3→2 오류 | 389 | 182 |
| validation 2→3 오류 | 64 | 64 |
| validation 2단계 F1 | 0.792297 | 0.875380 |
| validation 3단계 F1 | 0.883468 | 0.922608 |

**주의:** 수정된 validation 207건 중 202건이 E16이다. 나머지는 1개 실험의 5건이다. dev 수정도 2개 실험의 30건+2건이다. 실험 단위 2000회 bootstrap의 Macro F1 차이 구간은 dev `[0, 0.013325]`, validation `[0, 0.053004]`로 하한이 0이다. 광범위한 실험 개선으로 과장하지 않는다.

### 실패한 대조군도 확인했다

- 3을 한 번이라도 예측하면 바로 상태를 고정: dev에서 정답 **145건 훼손**. 단발성 3 신호로 고정하면 안 된다.
- 30초 연속 확인: dev 수정 0건, validation 7건으로 효과 대부분을 놓쳤다.
- p3≥0.9를 10초 요구: 두 split 모두 수정 0건. 이 모델에서는 유효한 조건이 아니었다.
- 확인 전의 모든 3을 2로 억제하는 단순 debounce: 10초 설정에서 dev 정답 15건, validation 정답 35건 훼손. 2→3 오판은 줄지만 실제 전환을 늦추는 대가가 생겼다.

0/10/30초, 확률 0.9 조건, 5/10초 debounce는 이번에 비교한 탐색 후보다. 10초는 외부에서 검증된 최적값이 아니다.

### 간격과 seed 민감도

같은 앙상블의 현재 프레임 확률을 고정하고, 과거 관측을 10초·15초 간격으로 모든 phase에서 성기게 만들었다. 10초 간격은 dev 31건/validation 208건, 15초는 dev 8건/validation 139건 수정했고 이 비교에서 정답 훼손은 없었다. 15초에서는 이득이 줄었다. Test 자체를 읽은 결과는 아니다.

반면 개별 seed에 같은 규칙을 적용하면 validation seed42에서 30건, seed44에서 35건의 정답을 훼손했다. **다른 B 재학습 결과나 MLP 출력에 동일 규칙을 붙여도 안전하다는 의미가 아니다.** 해당 앙상블 자체에서 추가 검증해야 한다.

상세: `results/scores.csv`, `per_experiment.csv`, `bootstrap.csv`, `seed_stress.csv`, `cadence_stress.csv`, `debounce.csv`.

## 5. 팀원의 단계별 MLP에 전달할 센서 의존성 근거

별도 MLP는 만들지 않았다. 입력 그룹의 가치를 비교하기 위해 고정 용량 HistGradientBoosting(7개 leaf, 150회, 동일 하이퍼파라미터)만 진단용으로 사용했다. 실험×단계 가중치를 균등화했고, 공식 Train 78개 실험을 GroupKFold 5개로 나누었다. 그룹별 결과를 보고 hyperparameter를 바꾸지 않았다.

| 입력 | Train 실험 단위 5-fold의 평균 2/3 Macro F1 |
|---|---:|
| 현재 온도 채널 | 0.87172 |
| 현재 온도+전압·압력 | 0.87498 |
| 현재 온도+화학 가스 | 0.86724 |
| 현재 전체 센서·가스 | 0.85410 |
| 센서+과거 이력 | 0.87915 |
| 위 입력+배터리/실험 조건 | 0.89301 |

여기서 지표는 **실제 라벨이 2·3인 행만의 binary Macro F1**이다. 앞의 전체 6클래스 Macro F1이나 0.92 제출 점수와 직접 비교하지 않는다.

센서 모델의 heldout permutation 민감도에서는 **현재까지 t1 최고값, 시작 대비 t1 상승량**이 dev/validation에서 주요 입력이었다. 압력의 시작 대비 변화와 60초 변화율도 일부 기여했다. 이것은 해당 보조 모델의 의존성이지 원본 B나 라벨 정의의 물리적 인과를 뜻하지 않는다. 온도에 화학 가스만 추가한 대조군도 평균 GroupCV가 0.87172→0.86724였고, 전압·압력 추가는 0.87498였다. 가스를 일괄 강화할 근거는 나오지 않았다. 이 수치는 새로운 fold에서 검증된 확정적 입력 우열은 아니다.

하지만 fit에서 학습한 이 모델로 B의 2/3 판정을 전부 대체하면 다음과 같다.

| 보조 모델 입력 | dev 전체 F1 | validation 전체 F1 |
|---|---:|---:|
| 교체 없음: B+45°C | 0.787871 | 0.712880 |
| 현재 온도 | 0.791143 | 0.709800 |
| 현재 온도+전압·압력 | 0.792192 | 0.707588 |
| 현재 온도+화학 가스 | 0.789710 | 0.706735 |
| 현재 전체 센서 | 0.788563 | 0.697080 |
| 과거 이력 포함 | 0.791366 | 0.692574 |
| 과거+실험 조건 | 0.793801 | 0.682979 |

따라서 **'2/3은 센서 모델 비중을 높이면 된다'는 일반적 결론은 지지되지 않는다.** 팀원 MLP에 t1 최고값·상승량·압력 변화 입력을 후보로 전달할 수는 있지만, B의 판정을 일괄 덮어쓰면 안 된다. 시작 대비 값은 처음 관측되는 시점과 Test 관측 범위가 달라질 때도 확인해야 한다.

실제 적용 우선순위는 (a) 45°C 규칙 보존, (b) t1<50 단방향 제약의 외부 일반화 점검, (c) 원본 B에서 확인된 3단계 상태 유지의 별도 검증, (d) MLP가 남은 첫 2→3 전환 검출을 얼마나 추가 개선하는지 확인 순서다. 3단계 이후 2로 되돌아가는 문제와 첫 전환을 놓치는 문제는 학습 목표와 평가를 나눠 보는 것이 적절하다.

상세: `results/sensor_groups_train_groupcv.csv`, `sensor_groups_holdout.csv`, `sensor_groups_permutation.csv`.

## 한계 및 재현

dev는 원본 B의 checkpoint 선택에 이미 쓰였고 validation도 반복 탐색했다. 이번 비교는 새로운 독립 Test 검증이 아니다. 센서 진단의 Train GroupKFold에서는 보조 모델만 재학습했으며 원본 B 전체의 새 outer CV 성능을 주장하지 않는다. bootstrap은 고정 예측의 조건부 분석이고 반복 선택 편향을 반영하지 않는다. Test 성능이나 0.93 달성을 주장하지 않는다.
