# 0.77 제출 회귀 감사 및 0.93 목표 판단

사용자 확인: `final_submit/submission_convnext_long4rule.csv`의 실제 제출 점수는 **0.77**. 원본 B는 이전 사용자 보고 약 **0.91**. 0.93은 목표이며 달성되지 않았다. 내부 점수를 실제 제출 점수로 환산하지 않는다.

## 최신 기록 반영

`origin/feat/gahyun`의 `52fd628`까지 pull하고, 갈라진 로컬 기록과 merge했다. 원래 작업 파일은 보존했다. 새 기록의 B 동결 4/5/6 전문가 V3는 내부 dev/validation 상승에도 제출 91→90이었다. 다른 작업 폴더의 제한 쌍 보정은 사용자 보고 0.8924970281, 이미지 사건 상태 보정은 0.8307340149였다. 작은 변경 수나 내부 bootstrap 개선만으로 실제 일반화를 보장하지 못한 선례다.

## 확인된 결과

아래는 저장 확률을 다시 읽어 계산한 6클래스 Macro F1이다. check 모델은 원래 fit만 학습했고 dev로 checkpoint를 선택했다. 공식 validation은 이미 여러 차례 탐색한 데이터다.

| 방법, 규칙 없음 | dev | validation | validation E16 제외 |
|---|---:|---:|---:|
| 원본 B | 0.781521 | 0.696346 | 0.814221 |
| ConvNeXt check | 0.832632 | 0.739802 | 0.856205 |
| ResNet50 check | 0.832854 | 0.724350 | 0.845170 |
| ConvNeXt/ResNet50 동률 평균 | 0.841740 | 0.731579 | 0.848076 |
| B 80% + 두 check 모델 각각 10% | 0.803488 | 0.697119 | 0.827960 |

마지막 조합은 dev 57건 개선/12건 악화, validation 72건 개선/142건 악화다. validation Macro F1 차이의 실험 단위 bootstrap 95% 구간은 **[-0.01644, +0.02692]**로 0을 포함한다. 따라서 이 후보를 0.91보다 좋은 제출이라고 추천할 근거가 부족하다. 결과를 보고 가중치를 더 탐색하지 않았다.

## 0.77 파일에서 달라진 것

- ConvNeXt check와 final의 Test 예측은 **164/3451행** 다르다(규칙 전). final은 fit+dev+validation을 학습한 별도 가중치다. check 점수는 final의 검증 점수가 아니다.
- ConvNeXt final은 규칙 전 B와 **298행**, 규칙 후 **300행** 다르다.
- 긴 4단계 규칙이 ConvNeXt final에서 바꾼 행은 **4행**이다. 규칙만으로 0.77의 주원인을 확정할 수 없다. 규칙 전 모델의 실제 제출 점수도 없다.
- ResNet50도 check→final에서 256행이 바뀐다. 같은 재학습 레시피의 미평가 모델로 교체할 근거가 충분하지 않다.
- 규칙 코드의 설명과 동작이 다르다. `long4_rule`은 4 이외의 예측이 나와도 시작시각을 초기화하지 않는다. 실제로는 '첫 4 이후 경과시간'이며 '연속 4 지속시간'이 아니다. 원본 모델과 기존 CSV를 바꾸지 않고 두 정의를 별도 비교했다.

이 수치는 모델 간 변화의 증거다. Test 정답이 없어 164행 중 무엇이 틀렸는지, 재학습·시간 입력·학습 도메인 중 무엇이 하락을 일으켰는지 분리할 수 없다.

## E16 해결과 제출 성능을 구분해야 하는 이유

기존 색 증강+첫 프레임 차분 `B_color`는 E16의 실제 5단계 정답을 6→0건으로 줄였다. 단순 색 보정을 다시 우선 추천하지 않는다. 과거 센서·경과시간·GRU·전문가도 이미 시도됐다.

원본 B에 기존 575초 규칙을 적용하면 validation은 **0.696346→0.783531**, E16의 5단계 정답은 **6→448건**으로 오른다. E16 제외 점수는 그대로다. 반면 진짜 연속 4 기준이면 validation 0.743399, E16 정답 248건이다. 즉 같은 '시계열 규칙'이라도 정의와 모델에 따라 결과가 크게 달라진다. 이 이득은 사실상 E16에 집중되어 Test 개선 근거로 사용할 수 없다.

동일 조건 Train의 5단계는 10~275초인 데 비해 E16은 2950초이며, E16은 관측 라벨상 3→5로 넘어간다. 다른 폴더의 전환 감사는 이 지원 부족을 이미 기록했다. '덜 파랗다'는 시각적 설명만으로 E16 실패 전체를 설명하거나, E16에 맞춘 보정으로 0.93을 예상하지 않는다.

## 현재 선택과 다음 실험

**현재 제출 기준은 실제 최고점 원본 B 유지**다. `results/submission_B_original_recovered.csv`를 원본 `submission_B.csv`와 ID/label/순서가 정확히 같은 것으로 검증했다. 0.77 파일을 덮어쓰지 않았다.

`results/submission_B80_equal20_fitonly_raw_candidate.csv`는 B 80% + check ConvNeXt/ResNet50 각각 10%, 재학습·시간 강제 규칙 없는 **연구 후보**다. 원본 B 대비 42행 변경이며 외부 점수는 없다. 내부 validation의 개선이 불확실하므로 자동으로 최고점 제출을 대체하지 않는다.

0.93을 위한 다음 단계는 또 다른 E16 보정이 아니라 **원본 B를 포함한 전체 학습 과정의 새로운 실험 단위 검증**이다. 동일한 outer fold에서 B와 사전학습 모델을 모두 재학습하고, scaler와 checkpoint 선택을 fold 내부로 제한해야 한다. 배터리 조건/진행시간이 다른 실험을 통째로 holdout하는 스트레스 평가도 필요하다. 이미 본 dev/validation에서 고른 레시피의 순위와 새 fold 순위를 비교하고, 통과한 레시피만 학습 범위를 확대한다. validation 포함 재학습을 성능 보증으로 취급하지 않는다.

현재 실행 환경에 `/dev/nvidia*`가 없고 `nvidia-smi`도 실패해 새 GPU 학습은 수행할 수 없다. 이번 작업은 저장 확률 기반 검증·실제 제출 기록 감사·복구·후보 생성까지 완료했다. **0.93 달성 또는 최적성은 확인할 수 없다.**
