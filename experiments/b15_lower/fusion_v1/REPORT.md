2026-11-15 · 원본과 S3의 보수적 통합

**통합 실행 코드를 완성했다. 추가 되돌림 보정은 활성화하지 않고 기존 S3 출력을 유지하도록 확정했다.** 이번 후보는 검증에서 하락하지 않았지만 예측 변경과 개선도0이어서, 통계적 성능·안정성 향상을 입증하지 못했다. 새 모델이 무조건 좋아졌다고 주장하지 않는다.

현재 S3 코드는 이미 정윤 원본에 S3를 더한 구조다. 같은 기본 모델에서 나온 두 출력을 독립 모델 앙상블처럼 취급하지 않았다. 이번 후보는 두 코드가 다른 예측을 낸 행에서만 원본으로 되돌릴지 판단하는 작은 L2 로지스틱 보정이다. 점수 기준0.95와 C=0.2를 결과 확인 전에 고정했다. 원본 확률·seed 일치도·관측된 합계 온도 정점과 하락·변화율·원본6 예측 지속시간을 사용한다. 점수0.95는 정답 확률95%라는 보장이 아니다.

검증과 채택 기준

- 공식 train+validation **97실험·43,722행 전체**, E16 포함, 바깥5-fold. 바깥 평가 실험은 교사 B의 학습·정규화·체크포인트 선택·원본 보정·새 보정 학습에서 제외한다. 새 보정 학습은 바깥 학습 자료 안의 실험별 held prediction으로 수행한다.
- 공식 train78실험만으로 최종 보정을 적합하고 validation19실험·10,200행 전체에서 확인한다. E16도 포함하며 제외 점수는 사용하지 않는다.
- 바깥5-fold × 관측8조건 모두 F1 비하락을 요구했다. 관측 조건별 전체 클래스 F1,6단계 FP·FN도 비악화를 요구했다. 전체 validation19실험도 같은8조건을 확인했다.
- 추가 보정 활성화에는 주 평가의 실제 개선과 paired bootstrap95% 하한>0, 전체 validation의 실제 개선도 요구했다. 지표가 같은 후보를 향상된 모델로 승인하지 않는다. 검증 결과를 보고 기준이나 점수 임계값을 낮추지 않았다.
- 기본 신경망은 기존 독립 학습 모델을 재사용했고, 모델69개 기록·전처리를 다시 감사했다. 리더보드 점수는 입력·선택에 사용하지 않았다. [고정 기준](protocol.json).

결과

| 항목 | 기존 S3 | 통합 후보 |
|---|---:|---:|
| E16 포함97실험 OOF F1 | 0.85252 | 0.85252 |
| OOF 6단계 오탐/미검출 | 222 / 78 | 222 / 78 |
| 제출 가중치의 전체 검증19실험 F1 | 0.77453 | 0.77453 |
| 전체 검증6단계 오탐/미검출 | 45 / 13 | 45 / 13 |
| 97실험의8개 관측 조건에서 예측 변경 | — | 0 |

5개 바깥 분할 각각에서 원본이 맞고 S3가 틀린 학습 사례46~63개, S3가 맞고 원본이 틀린 사례268~365개를 사용해 보정을 적합했다. 고정한 보수적 조건하에서는 원본으로 되돌릴 충분한 근거를 얻지 못해 평가 예측을 바꾸지 않았다. 따라서 비하락 검사는 통과했지만 개선 검사는 통과하지 못했다. 선택 결과는 **`fusion_enabled=false`, `deployment=current_S3`**다. [결정](decision.json), [학습 사례](gate_training.json).

완성된 실행 코드의 동작

- 두 코드가 같은 답을 낸 행과 공통4→3 보정은 보호한다.
- 새 보정의 학습 범위는 학습 disagreement에서만 적합한다. 결측·범위 밖 입력은 현재 S3를 유지한다.
- 현재 배포 artifact는 새 보정이 꺼져 있으므로 S3를 그대로 반환한다. 이를 성능 향상으로 표현하지 않는다.
- 기본 모델3개와 전처리의 파일 해시를 확인해 검증에 쓰지 않은 파일이 섞이면 예측 전에 오류로 중단한다.
- `submission_fusion.csv`는 현재 `submission_stage6.csv`와 모든3,451개 예측과 바이트 해시가 같다. 기존 파일은 덮어쓰지 않았다. 같은 채점 데이터·기준에서는 두 CSV의 점수가 같다.
- 새 특징·보정의 prefix508개, 합의 행·결측·범위 밖 입력·미래 행·행 순서·잘못된 전처리 파일에 대한 단위 검사4개를 확인했다.

사용

`fusion.joblib`은 이 폴더에 생성되어 있으며 Git에서는 제외한다. 저장소 루트에서 실행한다. `--base`에는 기존 원본 B 학습 폴더를 지정한다.

```bash
/home/ubuntu/venv/bin/python experiments/b15_lower/fusion.py \
  --input /home/ubuntu/data/battery_data_light/test/test.csv \
  --image-root /home/ubuntu/data/battery_data_light/test \
  --base /home/ubuntu/leewon/abc_runs/current_query_v1 \
  --artifact experiments/b15_lower/fusion_v1/fusion.joblib \
  --sample-submission /home/ubuntu/data/battery_data_light/sample_submission.csv \
  --output /tmp/submission_fusion.csv
```

[통합 추론 코드](../fusion.py), [검증 재현 코드](../validate_fusion.py). 검증 코드는 각 입력 경로와 새 출력 디렉터리를 인자로 받는다.

한계

예측을 바꾸는 새 모델이 미지의 모든 정답에서 비하락한다는 보장은 불가능하다. 이번에 점수 유지를 확인할 수 있는 근거는 실제 제출 예측을 그대로 유지했다는 점이다. 기존 모델의 E16 약점은 남는다. 데이터·가설을 이미 살펴봤으므로 새로운 맹검이 아니며, 내부 선택용 baseline은 해당 내부 학습 교사가 낸 in-sample 학습 확률을 사용해 바깥 OOF 표현과 보정 차이가 있다. 이 한계까지 기록하고 추가 보정은 비활성화했다.
